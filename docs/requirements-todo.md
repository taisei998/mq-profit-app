# 今後の要件定義に向けたメモ

今回は「今動いている機能をそのまま移植する」ことを優先し、新しい要件は追加していません。
ただし移植作業の中で、実務者の方に確認しておいた方がよさそうな論点がいくつか見つかったので、
次の要件定義のタイミングで検討してください。

## 運用まわり

- **同時編集**: 今は「後から保存した人の内容で上書き」される仕様です（旧アプリと同じ）。
  複数人が同時に同じ商品を編集する運用があるなら、排他制御や変更通知が必要かもしれません。
- **変更履歴**: 誰がいつ価格や粗利率を変更したかの記録（監査ログ）は今のところありません。
  粗利計算は経営判断に関わる数値なので、履歴を残す要件があるか確認が必要です。
- **削除の取り消し**: 商品・マスタの削除は即座に確定し、元に戻せません（旧アプリと同じ）。
  誤削除対策（確認以上のもの、ゴミ箱機能など）が必要か検討の余地があります。
- **バックアップ**: 現状はCSVエクスポートによる手動バックアップのみです。DBファイル自体の
  定期バックアップ運用（頻度・保管先）は未定義です。

## データ・機能まわり

- **受注データの蓄積**: 「③粗利集計」は毎回CSVをアップロードしてその場で集計するだけで、
  受注データ自体はDBに保存していません（旧アプリと同じ挙動）。月次推移やダッシュボードなど、
  過去の集計結果を後から振り返りたい要件があれば、受注データの永続化を検討してください。
- **カテゴリの固定リスト**: 商品カテゴリ（青果・精肉…など9種類）はコードに埋め込みの
  固定リストです。カテゴリ自体をマスタとして追加・編集したい場合は別途対応が必要です。
- **CSVインポートの対応範囲**: 今回作った商品一覧のCSV読込は「このアプリ自身が出力した
  CSV」のみに対応しています。旧アプリで過去に保存したCSVがそのまま読み込めるかは
  未検証です（形式は近いですが完全に同一ではありません）。

## 認証・権限

- OAuth2連携は後回しとのことでしたが、連携時に「閲覧のみ」「編集可」「マスタ管理者のみ」
  のような権限分けが必要かどうかは決めておくと連携がスムーズです。

## 本番環境・スケール

- 「サーバーレスで動く可能性がある」とのことでしたが、具体的な想定環境
  （AWS Lambda / Vercel / Azure Functions など）によって、DB接続のプーリング方法
  （Prisma AccelerateやRDS Proxy等）や、常駐サーバーが必要な機能（レート制限など）の
  実装方針が変わります。想定が固まったタイミングで設計を見直すのが良さそうです。
- 想定データ量（商品点数・月間受注件数）の目安があると、PostgreSQL/MariaDBへの
  切り替えタイミングやインデックス設計の判断がしやすくなります。
