# 社内アプリ基盤（ローカルアプリプラットフォーム）の要点

原典: https://docs.apps.lo-cal.work/ （**こちらが正。ここは実装時に効いた要点の抜粋**）

このアプリは **動的レーン（サーバーあり）** で公開する。

## 本番環境の前提

| | |
|---|---|
| 実行環境 | AWS ECS (Fargate)。**CPU 256 / メモリ 512、1タスク**。コンテナは使い捨て |
| データベース | 共有RDS（このアプリは**PostgreSQL**を選択）。本番はTLS必須 |
| ログイン | 社内認証システム（アクセスゲートウェイ）の OAuth2 Authorization Code + PKCE |
| ファイル / メール | S3 / SES（このアプリは現時点で未使用） |
| 公開URL | `https://<アプリ名>.apps.lo-cal.work` |

## 全レーン共通の決まり

- **リポジトリは常に非公開。GitHub Pagesの有効化は禁止。** 外部への転載も不可
- 認証情報・取引先名・単価・個人情報をコミットしない。**AIに読ませるために置いた資料も対象**
- Git と GitHub CLI 以外のソフトを勝手に入れない（Docker Engine は WSL2 経由のみ可・要承認。
  Docker Desktop は不可）。**npmパッケージ等のライブラリは制限の対象外**

## 実装で効いた点

**設定値**
- すべて環境変数から読む。Secrets Managerを自分で読みに行かない
- 必須の値が無ければ**既定値に落とさず起動を失敗させる** → `packages/server/src/config.ts`
- ただし「公開してからでないと決まらない値」（`ACCESS_GATEWAY_URL` 等）は必須にしない。
  欠けていても起動でき、その機能だけ使えない状態にする

**ポートとヘルスチェック**
- `PORT` は注入されない。固定8080で待ち受ける
- ヘルスチェックは**DBまで見る**。「200を返すだけ」にしない
- **必須の環境変数を1つ欠いた状態でも、ちゃんと200以外になることを実機で確認すること**（確認済み）
- `SELECT 1` 程度に留める。30秒ごとに永続的に呼ばれ続けるため

**ログ**
- 標準出力のみ。ファイルへ書かない
- 個人情報・リクエストの中身を出さない
- ヘルスチェック（User-Agent `ELB-HealthChecker/2.0`）は**アクセスログから除外**。
  ただし**エラーは除外しない**

**状態を持たない設計**
- SQLite・ファイルセッション・ローカル保存は禁止 → セッションは `sessions` テーブル
- 複数人で共有したいデータを localStorage に置かない。
  利用者ごとの一時的な状態（入力途中・表示設定）には使ってよい

**データベース**
- 接続プールは小さく明示的に（**5**）。共有インスタンスを他アプリと分け合っているため
- マイグレーションは単発コマンド。**起動のたびに自動実行しない**
- entrypoint が `migrate` 引数を受けたらマイグレーションに切り替わる
- **後方互換（expand-contract）で書く。** ロールバックしてもDBは戻らない

**ALBの下での動作**
- HTTPSはALBで終端。`X-Forwarded-*` を信頼する設定が要る（`app.set('trust proxy', true)`）
- アイドルタイムアウト60秒。長い処理はそのまま同期で返さない
- 自動更新・ポーリングを秒単位にしない（WAFのレート制限に拠点ごと引っかかる）

**社内認証**
- `permissions` スコープを必ず要求し、`<アプリ名>.access` **または** `<アプリ名>.*` で判定する
- 判定できなかったときは**通さない側に倒す**
- PKCEの値はサーバーのメモリに置かない（コンテナが複数台になりうる）→ `auth_flows` テーブル
- ログアウトはアプリ側のセッション破棄とゲートウェイへのリダイレクトの**両方**
- `post_logout_redirect_uri` は登録済み `redirect_uri` と**同一オリジンの絶対URL**

**コンテナ**
- `docker build -f Dockerfile.production -t <image>:<tag> .` で常にビルドできること
- マルチステージ必須。非rootで実行。軽量な公式イメージ
- ベースイメージのタグは**バージョン番号を含まない追従型**を優先する
- `.dockerignore` は「全部除外してから必要なものだけ許可」。
  ただし**許可したディレクトリ内の実ファイルは無条件に入る**ので `.env` 等は個別に除外する

## 公開までの流れ

1. 決まりを伝える → 2. 要件を整理 → 3. 本番用にコンテナ化 →
4. 公開申請（ジョブカン） → 5. 秘密情報をDXへ渡す → 6. DXの確認待ち

**レーンの割り当てを受ける前に実装を進めると作り直しになる**（このアプリは2026-10-05に動的レーンの案内を受領済み）。

公開後のコード変更は Pull Request → `main` へマージで自動デプロイ。
