# Amazon検索順位（SEO順位）自動記録バッチ — セットアップ

`packages/bsr` に同居しているバッチの手順書です。画面はありません。**毎朝1回、
「このキーワードで検索したとき自社商品が何番目に出るか」を測って、指定した
Googleスプレッドシートの指定セルに書き込みます。**

- **費用**: かかりません。
- **前提**: Googleアカウント（サービスアカウント）。Amazonのセラーアカウントは不要です。
- **取れるもの**: 検索結果1ページ目（既定）の中での自社商品の順位。
  **過去に遡ることはできません**（設定した日から先の分が貯まっていきます）。

> BSRバッチ（`docs/bsr-tracking.md`）とGoogleの設定・実行の仕組みは共通です。
> すでにBSRバッチを動かしているなら、[3. 設定ファイルを作る](#3-設定ファイルを作る) から読めば足ります。

---

## 先に知っておいてほしいこと

この数字の性質を分かったうえで使ってください。

- **ブラウザのシークレットモードと同じ条件で測っています。** Cookieを一切送らず、
  ログインもせず、キャッシュも使いません。自分のアカウントで見ると、過去に見た商品や
  買った商品が上に来て自社商品が実際より上位に見えることがありますが、この数字には
  その影響が入りません。手元で確かめたいときは、**Chromeのシークレットウィンドウで
  同じキーワードを検索**してください。普通のウィンドウで見た順位とは一致しません。
- **それでも環境で多少変わります。** Amazonの検索結果は、アクセス元のIP・時間帯・
  お届け先設定などでも入れ替わります。このバッチが出すのは「毎朝おなじ条件で測った値」です。
  **絶対値ではなく、上がった/下がったという変化を見るための数字**として使ってください。
- **広告（スポンサー枠）は既定で除外しています。** 検索結果の上部などに出る「スポンサー」
  表示の枠は順位に数えません（広告費を止めた瞬間に順位が急落したように見えるのを防ぐため）。
  画面で見えるとおりの順番が欲しい場合は `.env` の `RANK_VALUE="overall"` にしてください。
- **1ページ目 = 広告を除いて48件**です（Amazon.co.jpのPC版）。
  49位以降を追いたいときは `.env` の `RANK_MAX_PAGES` を増やしてください。
- **ぎりぎり圏内の商品は、日によって「順位あり」と「圏外」を行き来します。**
  Amazonは同じキーワードでも結果を出し分けることがあり、実測では同じ商品が
  数分の間に「15位」と「圏外」の両方を返しました（枠数は毎回48件で同じ）。
  順位が下位（30位以降）のキーワードほどこの揺れが出ます。**1日単位の上下ではなく、
  1〜2週間の傾向で判断してください。**
- **Amazonの利用規約は自動アクセスを想定していません。** 1日1回・キーワード数件という
  社内観測の範囲に留めてください。件数を増やしたり間隔を詰めたりすると、Amazon側から
  503で弾かれるようになります（そうなったらログに「アクセスを一時的に拒否されました」と出ます）。

## 1. シートの形

**`npm run rank:init` を実行すると、下の2つのタブを自動で作ります。**
既存のタブには一切触りません。すでに何か入っているセルも書き換えません
（何度実行しても安全です）。

### `SEO順位` タブ — 追跡リスト兼・今の順位

|   | A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|---|
| **1** | 最終更新 | 2026-09-10 08:00 | | | | | |
| **3** | **キーワード** | **現在順位** | **前日比** | **目標** | **ASIN** | **商品名** | **確認** |
| **4** | ミネラルウォーター 500ml | 5 | +2 | 3 | B0GVYMLPPC | 水500ml×45本 | 検索を開く |
| **5** | 雑穀米 | 圏外 | | 30 | B0GMHRB752 | 雑穀米450g×1袋 | 検索を開く |
| **6** | ←ここに書き足せば、次の実行から追跡が始まる | | | | | | |

**このタブが追跡リストそのものです。** キーワードを増やすときは、
**A列にキーワード、E列にASINを書くだけ**。設定ファイルはさわりません。
BSRタブに追跡したいASINを足すのと同じ感覚です。

- **A列・E列**: 人が書きます。**この2つがそろった行だけ**が対象になります
- **B列（現在順位）**: 毎朝バッチが上書きします
- **C列（前日比）・G列（確認）**: 空ならバッチが数式を入れます。**新しい行にコピーする必要はありません**
- **D列（目標）・F列（商品名）**: 自由に使ってください。バッチは触りません

前日比は**プラスが順位アップ**です（3位→1位なら `+2`）。順位が `圏外` の日をまたいだときや、
記録が1日分しかないときは空欄になります。

### `SEO順位履歴` タブ — 推移を貯めるところ

|   | A | B | C | D |
|---|---|---|---|---|
| **1** | | 自社 | 自社 | 自社 |
| **2** | | B0GVYMLPPC | B0GMHRB752 | B0GVYMLPPC |
| **3** | | 水500ml×45本 | 雑穀米450g×1袋 | 水500ml×45本 |
| **4** | **日付** | **ミネラルウォーター 500ml** | **雑穀米** | **天然水 500ml 24本** |
| **5** | 2026-09-10 | 5 | 圏外 | 26 |
| **6** | 2026-09-11 | 3 | 44 | 24 |

**キーワードごとの列はバッチが自動で増やします。** `SEO順位` タブにキーワードを1行足すと、
次の実行で履歴タブの右端に新しい列が作られ、見出しにそのキーワードが入ります。

列は**見出しの文字で探しています**（列の位置ではありません）。そのため、
あとから `SEO順位` タブの行を並べ替えても、履歴タブの列を動かしても、
過去のデータが別のキーワードとずれることはありません。

> 上の例のように見出しが4行目にある場合は、`rank-targets.json` に
> `"history": { "sheet": "SEO順位履歴", "headerRow": 4, "startRow": 5 }` と書きます。
> 既定は「1行目が見出し、2行目からデータ」です。
>
> 日付を先の日付まであらかじめ入れておいても問題ありません。
> バッチはその日の日付の行を探して書き込みます。

> 履歴が不要なら、`rank-targets.json` から `history` の行を消してください。

## 2. Google側の準備（サービスアカウント）

BSRバッチと同じものを使います。まだなら `docs/bsr-tracking.md` の
「2. Google側の準備」をそのまま実施してください。要点だけ再掲します。

1. Google Cloud Console で **Google Sheets API** を有効化
2. **サービスアカウント**を作り、JSONキーを `packages/bsr/google-service-account.json` に保存
3. **書き込み先のスプレッドシートを、そのサービスアカウントのメールアドレスに「編集者」で共有**

3を忘れると403になります。エラーメッセージに共有すべきアドレスが出ます。

## 3. 設定ファイルを作る

`packages/bsr/rank-targets.example.json` をコピーして **`rank-targets.json`** を作ります
（`.gitignore` 済みです）。**キーワードはここには書きません。** 一度決めたらほとんど触りません。

```json
{
  "sheet": "SEO順位",
  "updatedCell": "SEO順位!B1",
  "history": { "sheet": "SEO順位履歴", "headerRow": 4, "startRow": 5 }
}
```

| 項目 | 説明 |
|---|---|
| `spreadsheetId` | スプレッドシートURLの `/d/` と `/edit` の間の文字列。省略すると `.env` の `SPREADSHEET_ID` を使います |
| `sheet` | 追跡リスト兼・現在順位の表になるタブ名。既定は `SEO順位` |
| `updatedCell` | 省略可。実行日時をここに書きます。「今朝ちゃんと動いたか」がシート上で分かります |
| `history` | 省略可。`{ "sheet": "タブ名", "headerRow": 見出しの行, "startRow": データ開始行 }`。省略すると履歴を残しません |
| `layout` | 省略可。既定と違う列を使いたいときだけ。`{ "headerRow": 3, "startRow": 4, "keyword": "A", "rank": "B", "diff": "C", "asin": "E", "link": "G" }` |

`layout` の `diff` と `link` を `null` にすると、前日比・確認リンクの数式を入れません。

`.env` で変えられる設定（すべて省略可）は `packages/bsr/.env.example` の
「Amazon 検索順位（SEO順位）バッチ」の節にまとめてあります。よく使うのは次の2つです。

- `RANK_VALUE="overall"` … 広告を含む、画面に見えるとおりの順番を書く
- `RANK_MAX_PAGES=3` … 3ページ目まで探す（1ページ目に無い商品を追うとき）

## 4. シートを用意する

設定ファイルができたら、タブと見出しを自動生成します。最初に1回だけで十分です。

```bash
npm run rank:init
```

```
[init] タブ「SEO順位」: 新規作成しました
[init] タブ「SEO順位履歴」: 新規作成しました
[init] SEO順位: 見出しを用意しました。4行目以降のA列にキーワード、E列にASINを書いてください。
[init] SEO順位履歴: 見出しを用意しました。キーワードごとの列は、バッチが実行時に自動で増やします。
```

できあがったら、**`SEO順位` タブのA列にキーワード、E列にASINを書いてください。**
ここからは設定ファイルを触る必要はありません。

## 5. 動作確認

書き込みをせず、取得だけして結果を表示します。**まずこれを実行してください。**

```bash
npm run rank:check
```

こういう出力になれば成功です。

```
[rank] 基準タイムゾーン: Asia/Tokyo
[rank] 対象ドメイン: www.amazon.co.jp / 順位の数え方: organic / 探索範囲: 1ページ
[rank] スプレッドシート: 商品管理
[rank] 追跡対象 2件:
       SEO順位!B2 ← 「珪藻土 バスマット」/ B0ABC12345  (主力商品)
       SEO順位!B3 ← 「バスマット 速乾」/ B0ABC12345
[rank] 「珪藻土 バスマット」/ B0ABC12345: オーガニック 12位 / 48件中（広告込みの見た目では15番目）
```

## 6. 毎朝8時に自動で実行する（Windowsタスクスケジューラ）

実行用のバッチファイル `packages/bsr/rank-daily.bat` を用意してあります。
タスクスケジューラにはこれ1つを指定してください。

1. タスクスケジューラを開き「基本タスクの作成」／名前は `Amazon検索順位` など
2. トリガー: **毎日 8:00**
3. 操作: プログラムの開始
   - プログラム: `C:\Users\pc424\Documents\apps\ec-ai\packages\bsr\rank-daily.bat`
   - **引数・開始場所は空のまま**（バッチが自分で自分の場所に移動します）
4. 作成後、タスクのプロパティで「スリープを解除して実行」を有効にすると取りこぼしが減ります

コマンドで作る場合は、管理者権限のPowerShellで次の1行でも同じです。

```powershell
schtasks /Create /TN "Amazon検索順位" /TR "C:\Users\pc424\Documents\apps\ec-ai\packages\bsr\rank-daily.bat" /SC DAILY /ST 08:00 /F
```

実行結果は `packages/bsr/logs/rank.log` に追記されます。動かないときはまずここを見てください。

> `rank-daily.bat` は **Shift_JIS・改行CRLF** で保存されています。UTF-8やLF改行で
> 保存し直すと、cmdが日本語のコメント行を解釈できずエラーになります。

**パソコンが起動していない時間は実行されません。** その日ぶんが抜けた場合、あとから
埋めることはできません（Amazonが過去の順位を返さないため）。取りこぼしを避けたい場合は、
常時起動しているPCやサーバーにタスクを置いてください。

BSRバッチと同じ時刻に重ねる必要はありません。別々のタスクとして登録してください。

## 仕様のメモ

- **順位の数え方**: 検索結果ページのHTMLから、商品1件ぶんの枠を上から順に数えます。
  枠に `AdHolder` というクラスが付いていればスポンサー（広告）枠です。
  `organic` では広告枠を飛ばして数え、`overall` では飛ばさずに数えます。
- **同じ商品が広告と自然検索の両方に出ている場合**、`organic` では自然検索側の順位を採用します。
  ログには「広告込みの見た目では○番目」と併記されます。
- **取得に失敗したキーワードのセルは書き換えません。** 前日の値がそのまま残ります
  （503で取れなかった日に「圏外」と書いて、順位が落ちたように見えるのを防ぐため）。
  失敗があった場合、バッチは終了コード1で終わります。
- **アクセス間隔**: キーワード1件ごとに6秒あけ、503が返ったら5秒→10秒→20秒と
  待ち時間を伸ばして最大4回まで再試行します。
- **ページ数**: `RANK_MAX_PAGES` を2以上にしても、対象商品が見つかった時点で
  それ以降のページは取りに行きません。
- **`rank:init` は追記しかしません。** 空のセルにだけ書き込むので、あとから
  目標値やメモを手で入れても、次に実行したときに消えることはありません。
- **キーワードを足したとき**にバッチがやること: ①その行のB列に順位を書く
  ②C列とG列が空なら数式を入れる ③履歴タブの見出しにそのキーワードが無ければ、
  右端に列を作って見出しを書く。**人がやるのはA列とE列を書くことだけです。**
- **キーワードを追跡から外したい**ときは、`SEO順位` タブのその行を削除してください。
  履歴タブの列はそのまま残ります（過去のデータを消さないため）。不要なら手で消してください。
- **同じキーワードを複数のASINで追う**場合、履歴の見出しは `キーワード (ASIN)` になります。
  1つのASINだけで追っているうちはキーワードだけの見出しです。
- **履歴タブへの書き込み**は1日1行です。同じ日に2回実行すると、その日の行を上書きします。

## よくあるエラー

| ログに出る文字 | 原因と対処 |
|---|---|
| `設定ファイルが見つかりません` | `rank-targets.json` を作っていない。`rank-targets.example.json` をコピーしてください |
| `次のタブが見つかりません` | `cell` のシート名（タブ名）の打ち間違い。実在するタブ名がログに一覧表示されます。`npm run rank:init` でタブごと作ることもできます |
| `追跡対象が1件もありません` | `SEO順位` タブのA列（キーワード）とE列（ASIN）が両方そろった行がない。片方だけの行は飛ばされます |
| `飛ばしました → ○行目: …` | 書きかけの行。ASINが10桁でない、キーワードが空、などをそのまま知らせています |
| `履歴に新しい列を作りました: …` | 正常です。新しいキーワードのぶんの列ができたという報告。**身に覚えがないキーワードが出た場合は、`history` の `headerRow` が実際の見出し行とずれていないか確認してください**（見出しを見つけられず、列を作り直してしまいます） |
| `スプレッドシートへのアクセスが拒否されました (403)` | シートをサービスアカウントに「編集者」で共有し忘れ。アドレスはエラー内に出ます |
| `Amazonがアクセスを一時的に拒否しました (503)` | 短時間に叩きすぎ。キーワード数を減らすか `RANK_INTERVAL_MS` を増やしてください |
| `CAPTCHAまたはロボット判定のページが返りました` | 同上。しばらく間を空けてから再実行してください |
| `検索結果が1件も読み取れませんでした` | Amazon側のページの作りが変わった可能性。`src/search.ts` の判定を直す必要があります |
